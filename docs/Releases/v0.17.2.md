# CaveTrip Manager v0.17.2

## Purpose

Hotfix for two regressions reported after v0.17.1:

1. `/trip-reports` displayed the application 404 page because the route table on the deployed installation did not contain the Trip Reports routes.
2. The Users list no longer displayed the user's role or Edit link, preventing normal user administration.

## Changes

- Restores the complete v0.17 route table, including:
  - `/trip-reports`
  - `/trip-reports/show`
  - `/trip-reports/create`
  - `/trip-reports/edit`
  - Trip Report create/update POST routes
- Restores the full v0.16 User administration implementation:
  - Role column
  - Edit link
  - Phone
  - Active state
  - Last-login display
  - Complete Edit User form
  - Assign `super_admin`, `admin`, `member`, or `guest` as permitted
  - Password replacement
  - Account activation/deactivation
- Version bumped to 0.17.2.

## Apply

```bash
unzip cavetrip-manager-v0.17.2-routing-user-admin-hotfix.zip
cd cavetrip-manager-v0.17.2-routing-user-admin-hotfix
./scripts/apply-release.sh /opt/cavetrip-manager

cd /opt/cavetrip-manager
php -l routes/web.php
php -l app/Controllers/UserController.php
php -l app/Services/UserService.php
php -l app/Views/users/index.php
php -l app/Views/users/form.php

git diff
git add .
git commit -m "Fix trip report routes and restore user administration"
git push origin main

sudo /var/www/trips.sixridgesgrotto.org/update.sh
```

## Test

1. Visit `/health` and verify version `0.17.2`.
2. Visit `/trip-reports`; the search/list page should load instead of 404.
3. Visit `/users` and verify your `super_admin` role is visible.
4. Click **Edit** for your user.
5. Confirm name, email, phone, role, active state, and password fields are available.
6. Do not change your own role during this test unless intended.
