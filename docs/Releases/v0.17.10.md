# CaveTrip Manager v0.17.10 — Operations Dashboard

This release turns the main dashboard into an operational home screen and removes an unused waiver-template list column.

## Changes
- Removes the old development-oriented "Next Build Areas" content.
- Replaces generic installation counts with operational metrics:
  - Upcoming Trips
  - Participants on upcoming trips
  - Waivers Pending
  - Trip Reports Needed
  - Caves
- Adds an Upcoming Trips panel with date, cave, leader, roster, waiver progress, and status.
- Adds a Needs Attention panel for unsigned waivers, near/full capacity, signup windows closing within seven days, and missing trip reports.
- Adds practical Quick Actions for Create Trip, Add Cave, Add Landowner, Waiver Templates, and Email Settings.
- Gives guest users a simpler participant-oriented dashboard.
- Removes the unused Status column from the Waiver Templates list page.
- Restores/ships `DashboardStatsService.php` explicitly so dashboard statistics are self-contained and do not depend on an older release file lingering on the server.
- Cache-busts `app.css` to v0.17.10.
- No database migration is required.

## Apply
```bash
unzip cavetrip-manager-v0.17.10-operations-dashboard.zip
cd cavetrip-manager-v0.17.10-operations-dashboard
./scripts/apply-release.sh /opt/cavetrip-manager

cd /opt/cavetrip-manager
git diff
git status
git add .
git commit -m "Release v0.17.10 operations dashboard"
git push origin main

sudo /var/www/trips.sixridgesgrotto.org/update.sh
```

## Test
1. Open `/dashboard` as an admin/member and confirm there is no "Next Build Areas" section.
2. Confirm the top cards show operational counts instead of grotto/user totals.
3. Confirm upcoming trips list date, cave, leader, roster and signed counts.
4. Confirm unsigned waivers appear under Needs Attention when applicable.
5. Confirm a trip at >=80% capacity is flagged as Near Capacity and a full trip as Trip Full.
6. Confirm a signup close time within seven days is flagged.
7. Confirm completed trips without reports appear as Trip Report Needed.
8. Open `/waiver-templates` and confirm the Status column is gone.
