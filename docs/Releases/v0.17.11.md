# CaveTrip Manager v0.17.11 — Last Login Hotfix

This release fixes the Users page "Last Login" value so it updates after each successful database-authenticated login.

## Cause
`AuthService::attempt()` authenticated the user and created the session, but never wrote to `users.last_login_at`.

## Fix
- After successful password verification, updates `users.last_login_at = NOW()`.
- Failed login attempts do not change the timestamp.
- No database migration is required because `last_login_at` already exists.

## Apply
```bash
unzip cavetrip-manager-v0.17.11-last-login-hotfix.zip
cd cavetrip-manager-v0.17.11-last-login-hotfix
./scripts/apply-release.sh /opt/cavetrip-manager

cd /opt/cavetrip-manager
git diff
git status
git add .
git commit -m "Release v0.17.11 last login hotfix"
git push origin main

sudo /var/www/trips.sixridgesgrotto.org/update.sh
```

## Test
1. Note the current Last Login value for a test user on `/users`.
2. Log out.
3. Log back in as that user.
4. Return to `/users` as an administrator.
5. Confirm Last Login now shows the new successful login time.
6. Try one failed login and confirm it does not update Last Login.
